# 4.13.0 完整主题与组件审读

用户明确指出4.12仅换强调色、白且空，随后强调组件本身的配色和质感也应调整。本轮先从4.12新鲜浏览器资料检查，再实施完整工作区主题和组件方案；依据和范围见[任务书](../../../../THEME_BRIEF.md)。

## 基线发现

[八图实际审查](baseline/REPORT.md)确认两套强调色的大背景、侧栏和任务面完全相同，设置则在大宽板上只摆三个下拉框。淡中性色面积计算是该组截图的描述，不是美感分数。审查与后续候选均使用本轮真实合成资料，没有读个人任务。

## 组件整改

| 部位 | 本轮改变与用途 |
| --- | --- |
| 完整主题 | 四套配色各有亮暗的导航/背景/页头/内容/输入/浮层/文字，选项可以直接预览整套工作区。 |
| 导航 | 深色骨架采用独立文字、图标、悬停、选中与焦点，避免全局浅色强调色落在深导航上消失。 |
| 任务与日期 | 宽屏标题/标签左侧、日期/时距右侧；窄屏自然回流，时钟与AM/PM同组。 |
| 工具与按钮 | 主操作、浮起的次级操作、文字操作及危险操作有不同表面；保留按压和减弱动态效果。 |
| 编辑器 | 头尾raised、工作面content、字段inset；焦点保留单一明确轮廓，长表单可滚动到底。 |
| 菜单与标签 | 危险项独立分组；项目徽标与标签不同权重，任务悬停和分隔不再是一片重灰膜。 |
| 日历与日程 | 小月历/即将到期归于一个参照区；事件采用tonal chip与语义点，今天、选日和单日日程各有层级。 |
| 统计 | 连续分段操作带替代三个分散灰卡，回顾与项目安排在桌面并列；数据条清楚可见、项目面板按内容自然高度。 |
| 勾选 | 普通/批量选择使用主题onPrimary标记；父任务完成与子任务使用独立成功色及白色勾，保护亮暗对比。 |

原有任务、提醒、重复、今日计划、归档、备份恢复、视图与草稿能力保留。使用预览主题不会写入任务或重建任务节点。

## 审读与边界

根代理先后亲用桌面、390px、320px及980px的任务、编辑器、菜单、四视图、主题预览、五类设置、导入预览、维护确认和帮助。独立审读保留原始fix报告与限定ship复核，未使用工具通过数代替视觉判断。

首次组件复看中，审查脚本误以为空工作区导入也会要求下载替换前快照；实际当前0任务直接导入是原有保护规则，已导入的6项真实导出任务完整，后续错误点击没有作为产品缺陷。正常非空导入预览另作实际查看和取消。
