# 4.13.1 操作路径与主动细节审查

用户指出主动检查更新缺失、添加任务入口过深，并要求自行发现同类细节。本轮沿用4.13主题，先亲用两个路径，再独立审查项目、今日计划、搜索、菜单、批量及设置返回。

## 发现与修复

| 真实问题 | 修复后的行为 |
| --- | --- |
| 添加任务先展开快速记录，再找完整表单 | 顶栏主按钮直接开表单；相邻箭头保留快速记录，原草稿可接续。 |
| 没有主动检查更新 | 帮助与关于提供检查按钮、明确状态，以及就绪后的刷新；不刷新未保存内容。 |
| 项目中新建默认Inbox，保存后当前范围看不到 | 默认当前项目或无项目范围，全部项目才默认Inbox；显式输入的项目优先。 |
| 今日计划中新建后不在计划内 | 当前计划中新建与快速记录保留计划归属，截止日期独立。 |
| 计划已有任务但搜索无匹配却提示计划为空 | 显示准确空结果；清除搜索与筛选后保留今日计划。 |
| 320px撤销文字被挤成竖排 | 使用保留完整可访问名称的紧凑图标。 |
| 快速记录展开时向上菜单被工具栏遮住 | 菜单层级高于工具栏，编辑等操作可实际点击。 |
| 存储初始失败时新更新按钮未绑定 | 更新事件纳入只绑定一次的基础事件，失败模式仍可检查及应用更新。 |

[独立原始审查](independent-detail-review/README.md)与[三条路径的桌面/手机复核](independent-detail-review/FINAL-REVIEW.md)保留修前和修后身份。原审查中的统计渐入画面未接受，另有稳定截图。菜单遮挡有[实际几何、点击和仅浏览器临时修正证据](menu-overlap/README.md)，随后源码采用相同层级修正。

两张入口基线保留原两步操作；捕获时语言资源已先行将“更多选项”改为“完整表单”，不声称是逐字未改的4.13.0档案。人工步骤中误写`taskDescription`的审查脚本超时另作记录，实际字段为`taskDesc`，不当作产品缺陷。
