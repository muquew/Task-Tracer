本轮保留 **2 个窄屏易用性问题**，均为 P2；没有在已实际走过的工作区流程中复现数据丢失、菜单不可操作或返回路径中断。不为了达到条数增加假设性问题。

基线：主代理提供的 8dc7ca4 / APP4.13.2；开始时 `index.html` SHA-256 为 `79693a476cd75b46df78b71890f9a3a89aef2eb08aa8a2af701c07c4b801c1ad`。本轮新 Chromium 154.0.8037.57 context，正常 ProductionHeaderHandler CSP，`prefers-reduced-motion: no-preference`。通过真实 UI 建立 8 条合成任务，分属 3 个项目，包含逾期、当天、明天、无期限、标签与 3 个子任务；操作中完成 1 条任务。覆盖 1440×1000、390×844、320×740。所有 20 张保留 PNG 均已打开检视；先前未定位到详情的截图已重截覆盖，未把自动化中途异常当作产品问题。

## P2-1：320px 批量操作时，筛选和操作区占满首屏，无法同时核对所选任务

![320px 批量操作更多展开](12-small-mobile-batch-more.png)

步骤：列表打开“筛选” → 点选择任务图标 → 选择两条任务 → 展开“更多操作”。

实际：批量入口位于展开的筛选区，因此项目、状态、排序三行仍留在上方。320px 下批量工具自身为 **292×261px**，位于 y=432–693；底部导航从约 y=676 开始。在截图 12 中，看不到任何一条所选任务；必须来回滚动核对任务，再返回上方执行操作。390px 也明显被占用（截图 10、11），但操作仍可完成。

期望：选择后可同时看见至少一条所选任务与当前选中数量/主要操作；非必要筛选不继续占据主要视口。

建议：把选择入口放进直接可见的任务工具区；进入批量后收拢筛选内容，并用紧凑的“已选 N 项 / 完成 / 更多 / 退出”操作条。展开更多时采用受控菜单或底部面板，保留选择数和当前任务上下文。完整筛选条件保留为摘要，避免清掉实际 scope。

具体位置：`#batchModeBtn` 位于 `#toolsDrawerContent`；`#batchToolbar`、`.batch-toolbar-summary`、`.batch-toolbar-actions`、`#batchMoreActions[open]` 和 `.batch-more-panel` 的布局叠加造成高度增长。相关状态入口为 `setBatchMode`、`setToolsDrawerState` / `syncToolsDrawer`。不需要改变批量数据处理逻辑。

补充健康：实际执行“移动到项目”后有目标项目反馈；全局撤销恢复两条任务的原项目。改变搜索为“登录”后，不再匹配的两条任务会从选择中清除，显示“已选择 0 个任务”（截图 20），没有隐形选中项继续参与批量动作。

## P2-2：320px 统计入口仍强制三列，解释小字被压成碎行

![320px 统计待处理卡片](14-small-mobile-stats.png)

步骤：小屏进入统计，查看“待处理”中的逾期、今天截止和无期限三个入口。

实际：每列只有约 **89.3px**，卡片高约 **170px**；11px 说明如“截止日期为今天的未完成任务”被拆成 3 行，末尾单独一个“务”。三个按钮又分别重复“查看任务”。数字和入口本身可操作，但用户要从低信息密度的小字中提取相同的“未完成任务”限定。

期望：任务数量和分类可迅速比较，必要限定只解释一次。

建议：窄屏用更紧凑的分类行或两列/一列布局；把“仅统计未完成任务”的限定放在节说明中，去掉卡片内重复长说明和重复“查看任务”字样，保留完整可访问说明。不要仅继续缩小字号。

具体位置：`.stats-action-grid` 固定 `repeat(3,minmax(0,1fr))`；移动样式将 `.stats-action-hint` / `.stats-action-link` 降到 11px。构造函数为 `createStatsWorkload`、`createStatsActionCard`，核心 selectors 为 `.stats-action-label`、`.stats-action-value`、`.stats-action-hint`、`.stats-action-link`。

补充健康：点已完成数量会进入对应列表，搜索条件清楚显示 `status:completed`，有“返回统计”入口；实际返回成功。详情里的 4 个数量和 2 个比例没有互相覆盖（截图 15、16）。
