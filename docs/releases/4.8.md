## Scope and limits

Calendar pagination limits displayed nodes, not full-workspace matching, grouping or storage work. Older 4.6/4.7 calendar measurements remain historical evidence; no new 4.8 latency, heap or device guarantee is inferred from a card cap. Manual/batch rendering remains full-size where needed to retain its semantics.

The composition checks exercise application event handling. Actual Chinese/Japanese and other operating-system keyboards, mobile candidate selection, external keyboards and assistive technology still need the [manual device checklist](../manual-device-checklist.md). No real-device or system-notification pass is added here.

Recovery checkpoints can retain task text that no longer appears in the current list. Their preview uses a bounded scroll area, begins with 100 task-name/status rows and adds 100 per request, with full counts. Export downloads the selected checkpoint as task JSON 2.4 (`type: backup`) without updating current backup time/revision coverage. Clear history compares the reviewed ordered checkpoint IDs inside a config-only transaction; changed history is kept and reopened for a new review. Clearing changes neither current tasks, views, settings, backup metadata nor Undo; subsequent task writes can create new checkpoints. A browser download beginning is not proof that a usable file was retained. Any exported checkpoint remains unencrypted user data and needs review before sharing.

## Known follow-up: quick-add text after a storage failure

A new isolated probe reproduced a real 4.8 gap after the payload freeze. A single task-add quota failure left the database and the original 28-character quick-add input unchanged, including whitespace and Chinese/scoped text. Pressing the actual Retry button then reloaded the page because no full-form recovery queue existed, and the unsaved quick-add text became empty. This is loss of unsubmitted input, not a partial database write.

Quick-add text is not covered by the full task-form recovery queue. Retain a separate copy before Retry or reloading after a storage failure. The then-unregistered probe failed its original-text retention assertion; it was not part of the 38-program result and must not be misrepresented as covered by that result.

The [4.8.1 candidate](4.8.1.md) corrects this with same-page Retry, departure protection, copyable input in failure mode and capture-option retention; its separate complete 39-program run passed. The frozen 4.8 artifact and failed report remain unchanged. The known gap in this older package prevents treating 4.8 itself as commercial-ready.
