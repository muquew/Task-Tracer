# 4.6 candidate notes

Prepared on 2026-10-23. This working-tree candidate continues the local-first commercial-product objective; it is not a published release or a commercial purchase offer. The public license is unchanged, and no account, purchase check or remote task service is introduced.

## Portability and daily use

- Transfer saved views is available in the main menu and command palette. A separate JSON 1.0 file carries saved searches, filters, projects, sorting and layouts. Export reads the latest database configuration and does not change task data, device preferences or the task-backup timestamp.
- View import strictly validates the envelope, checksum, fields, 12-view limit and 1 MiB file size. Its preview shows additions, duplicates and capacity skips. Atomic merge preserves existing IDs, labels and order; new imports receive new IDs. It never evicts existing views. Changed current views require review and another confirmation. The checksum detects file changes, not authorship.
- View files may contain private search terms and project/tag names. Review them before sharing. Task JSON backup remains version 2.4 and excludes saved views, app preferences and recovery history; the view file is a separate transfer path.
- Rapid search followed by Save view now captures the visible search input before the rendering debounce. Distinct quick searches remain distinct views. No-deadline and sort labels in the preview are translated.
- Task-file reading shows cancellable progress. Cancelled or superseded reads cannot open an old preview over a later task draft or override a newer file selection. View-file reads follow the same latest-selection rule.

## Concurrent changes and safety

- A task import preview records the task revision it describes. If background work refreshes tasks while that preview is open, confirmation rebuilds the preview from current data and resets checksum/snapshot approvals. The selected file is retained, but new explicit confirmation is required. Unseen database changes still trigger the transactional conflict guard.
- Delete, batch delete, clear-completed, archive-completed and recovery confirmations capture their opening revision. A later observed change invalidates those approvals. Their failure path retains newer data.
- Conflict feedback covers changes from other windows and overlapping actions in the current window.
- Task-write transactions capture the expected revision when invoked, before asynchronous IndexedDB callbacks. A queued stale writer cannot inherit a refreshed global revision and overwrite a newer edit. A rapid second independent write can safely conflict rather than assuming it was based on the first write's result.
- Regression tests reproduce the prior replacement-import and queued-write data loss, then verify protection, fresh preview/snapshot continuation and Undo against the latest data.

## Dates and larger workspaces

- Editing an unchanged deadline preserves its original exact instant and time zone, including the second repeated hour during a daylight-saving rollback. Description-only edits no longer move that deadline by an hour. Past deadlines are permitted in the task form for overdue edits and historical entry.
- Explicit-zone wall-time formatters and timezone-validity checks use bounded caches (64 formatters and 128 names). Device-local timezone lookup remains live; an invalid zone's fallback does not stick to the former device timezone. Undated tasks avoid unnecessary timezone work.
- Import conflict controls initialize only when Merge is selected. They display 100 rows at a time with Show more. A labeled bulk action applies Keep both, Skip import or Replace local to all matching names, including unrendered rows. Changing it resets individual choices; later individual overrides are supported. Nonmatching names are still added.
- Ordinary Timeline rendering starts at 100 cards and adds 100 on request. Dates remain chronological, undated tasks come last, group/overall counts include all matches and search covers the full dataset. Page state resets across relevant search/filter/view changes. Manual sort and batch mode retain full rendering.
- The extended round-trip test validates 1,000 and 10,000 dated tasks with six subtasks each, actual downloaded JSON and pre-import snapshots, full-field SHA-256 equality, deletion and checkpoint restoration. It returns browser-side history digests rather than transporting every checkpoint through the test driver. Current metrics and measurement limits are documented in [performance.md](../performance.md).

Calendar undated sections/day details, manual ordering and batch mode still render their full applicable task sets. Real-device mobile performance, installation, operating-system reminders and screen-reader behavior remain launch checks beyond browser automation.
