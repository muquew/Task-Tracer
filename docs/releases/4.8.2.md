The gap/fold policy applies to newly set or changed deadlines and next-occurrence calculation. Existing `dueAt` instants are retained; this change does not rewrite all old tasks. If an older version saved an incorrectly early instant for a nonexistent time, the current schema cannot recover the intended time reliably: review it and edit the deadline explicitly. Recurrence continues from the previous occurrence's actual saved wall time, without a separate hidden scheduling anchor.

The date conversion policy is visible beside the deadline controls. The overdue detail explicitly names ongoing dated tasks. The expanded accessibility workload reproduced further defects:

- A long saved-view name reached 462px on a real 390px viewport while its dialog ended at 380px. `overflow-wrap: anywhere` brings the measured name within 365px.
- The apply button's accessible name omitted visible scope/layout metadata, causing serious `label-content-name-mismatch`. Adding metadata passed the earlier Chinese focused scan, but the full run in English still found a mismatch with the complete visible name, including its CSS separator. The correction removes the explicit apply `aria-label` so native name computation uses the visible name/metadata; the action description remains in `title`.
- Flex layout compressed the delete button to 20.92px beside a long name. A fixed 32px flex basis/minimum preserves its target width.
- A pending 300ms search debounce rebuilt the saved-view chips while their delete confirmation was open. Cancel retained a detached × reference and sent focus to New task. Focus return now captures the stable view ID and apply/delete action, resolves the current matching control after rendering and falls back to Save view if it disappeared. Cancellation and successful deletion both use this helper.

The earlier four-scene Chinese focused accessibility rerun passed at 1280px and 390px in both themes. It did not cover the English state that failed in the full run; the permanent delete-view audit was expanded to eight scenes covering both languages, and all eight focused scenes now pass with native accessible names. The complete standalone accessibility program then passed. All seven deletion groups passed in Chromium, Firefox and WebKit before this latest accessible-name correction, including the new real search-input/300ms debounce reproduction: a pointer opens the confirmation while the old × is connected, advancing the actual timer detaches it, and Cancel focuses the new × for the same view without a database change. The strengthened visible/enabled/hit-test and physical mouse-click variant also passed in all three engines. These focused results do not convert the failed complete run into a pass. Browser event, virtual-clock and simulated mobile evidence does not replace actual operating-system input methods, notifications or real-device testing.
