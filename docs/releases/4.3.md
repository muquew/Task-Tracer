# 4.3 candidate notes

Prepared on 2026-10-22. This is a working-tree candidate, not a published production release. The owner has confirmed they are muquew; the public personal non-commercial license remains unchanged. [The commercial plan](../commercial-plan.md) proposes a separate owner-issued offer rather than implying that the archive grants commercial rights.

## Changes

- Ordinary lists initially display 100 matching tasks, with a visible full-match count and Show more. Search still includes tasks outside the rendered page. Query parsing and per-render search text are reused. [The 10,000-task local comparison](../performance.md) measured reload readiness changing from 7,306 ms to 2,167 ms and end-of-dataset search from 3,444 ms to 356 ms; these single cloud runs are not cross-device guarantees.
- Data safety displays origin storage estimates and persistence status. Persistence is requested only after a user action; granted, denied and unsupported cases retain task/export access. It does not replace separate backups.
- Checkpoint quota failures roll back atomically and retain emergency export, including readable task data when the startup write probe fails. A separately confirmed cleanup deletes only recovery history, preserves tasks/settings, and retries initialization.
- Database connections close on a version change. Blocked upgrades show actionable guidance rather than an indefinite loader, and affected windows retain an emergency-export path.
- Same-origin PWA tests upgrade from the baseline version, roll back, and upgrade again while preserving tasks and offline loading. This covers the unchanged IndexedDB schema only.
- Deployment script CSP uses hashes, with inline event handlers blocked and stale hashes rejected by validation. Inline styles remain allowed. Automatic Vercel analytics loading is removed. Local browser tests execute the actual configured CSP; production response headers still need separate verification.
- Fixed statistics buttons' accessible names and light/dark control/notification contrast. The pinned axe audit covers both viewport sizes, reduced motion, recovery/data safety dialogs and notifications; it waits for finite animations to finish.
- Added an engine-neutral desktop/mobile flow suite and Chromium/Firefox/WebKit CI matrix. A missing engine binary fails explicitly.
- Deterministic static distribution generation includes an integrity manifest and archive checksum. Tests compare two build outputs and run the extracted PWA, including persistence and offline reload. CI uploads the static artifact after checks; no command here publishes a release.

## Versions and compatibility

App/cache: 4.3. Translation resources: 4.27. IndexedDB remains version 2; task exports remain version 2.4. Existing task data and export compatibility are preserved. Close or refresh older pre-revision-aware tabs, including installed offline windows, before editing after an upgrade. Older clients cannot be assumed to increment the revision guard.

Manual ordering and batch mode retain full-list rendering. Timeline and calendar day details are not virtualized. Persistent storage and quota estimates are browser-controlled and may be unavailable. Browser reminders remain subject to operating-system/browser policy.

## Validation record

The unified command registers 14 check programs. The final integrated run and independently exercised checks use Python 3.12.14, Playwright 1.62.0, axe-core 4.14.0, and system Chromium 154.0.8037.57:

```bash
TASK_TRACER_BROWSER_EXECUTABLE=/usr/bin/chromium PYTHONDONTWRITEBYTECODE=1 python3 tools/check.py
```

The programs cover static/date/CSP consistency, the full existing smoke suite, transactional recovery, undo/stale-form conflicts, database lifecycle, persistence permission fallbacks, PWA upgrade/rollback, enforced CSP, large-workspace rendering/search, desktop/mobile critical flows, axe accessibility, and reproducible executable distribution artifacts. The final integrated 14-program run, including checkpoint/startup quota failures and confirmed history-only cleanup, completed with exit status 0. The verified static archive is `dist/task-tracer-4.3.zip` (23 files), SHA-256 `ff6b1da1c3e0eb9ed2c8ba672fc68762d0e5e6fff6fb45308136dac7dc32a728`. It was built from the modified working tree; the integrity manifest records that fact rather than claiming a clean released commit.

The download-domain policy was subsequently saved and published by the owner. Chromium 154.0.8037.57, Firefox 153.0, and WebKit 26.5 have now each passed the engine-neutral suite at 1280px and 390px, including CRUD, views, export/import, and unavailable-origin cache reload. The suite uses persistent disposable profiles, then shuts down its local server to verify network fallback. Chromium's full smoke separately retains browser-offline emulation.

Firefox needed execution outside this cloud filesystem sandbox because the sandbox mounted `/proc/self/uid_map` read-only. Browser sandboxing remained enabled in the successful run. WebKit used missing Debian shared libraries downloaded through signed Debian package metadata and extracted under `/workspace`; its bundled wrapper's private library path was supplied with those verified libraries. Because Playwright's host checker only consults the system ldconfig cache for a dlopen probe, the local WebKit run used its supported host-check override after independent library-load verification. Package/TLS integrity and all browser assertions remained enabled. Normal CI installs system dependencies and does not use that override.

An optional read-only production checker now verifies exact assets and deployment headers. It is separate from the default checks, with a disabled-by-default manual CI input. Its success and missing-header rejection were tested against local fixtures. This cloud instance's current attempt to access the public domain was denied by the outbound proxy; that is not evidence of a website defect.

Still unverified: a public HTTPS deployment and actual response headers, real-device/screen-reader coverage, unusually large descriptions/subtask counts, storage eviction on real devices, and payment/order delivery. Hashes detect file changes; they do not constitute a publisher signature or an issued commercial license.
