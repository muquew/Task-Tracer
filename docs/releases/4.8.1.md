## Confirmed problem

A genuine single task-add quota failure left the database and a 28-character quick-add input unchanged. Actual Retry reloaded the page when the full-form recovery queue was empty, clearing that unsubmitted input. The failure was text loss after Retry, not a partially committed task. The raw text included whitespace, Chinese text and scoped capture syntax.

## Corrected behavior

- Keep nonempty quick-add text in the current page during storage failure. Make the unavailable input read-only and selectable for copying; keep task submission unavailable until storage recovers.
- Retry storage in the same document when quick-add text or full-form recovery drafts remain. Preserve exact raw text and source-URL capture options through failed retries and recovery.
- Request a browser departure warning for unsaved quick-add text as well as the existing form/queue cases. Browser policy still controls actual prompts; this is not durable autosave.
- After storage recovery, let the user explicitly submit once. Do not automatically replay a failed add, duplicate a task or lose captured source metadata. Coexist with the full-form draft queue without overwriting an open form.

Quick-add text remains memory-only and needs an external copy before refresh, close or crash. The existing `task-draft` file is for retained full-form drafts; no quick-add download/import feature is claimed here.
