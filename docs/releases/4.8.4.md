The static syntax/date guards also required a tooling correction: a legal regex containing a quote was mistaken for a comment, and a global date token check depended accidentally on the quick-date implementation. The runtime had no such comment. `static_syntax_test.py` now passes 30 legal syntax cases, rejects real comments and rejects eight scoped UTC-date mutations; the comment-free runtime rule remains.

Text edited intentionally still uses the existing normalizers. Quoted tags apply to the full task-form field, with examples such as `"research, notes", ordinary` and `"a""b"`; they do not introduce a task JSON/CSV file-format migration. Invalid quick-add calendar tokens stay task text; a separately valid time token retains existing time-only behavior. Relative words use the local date at submission. New nonexistent deadline times still follow the existing forward-gap policy; earlier incorrect stored instants cannot reliably reveal the original intended time and are not guessed or bulk-rewritten.

Recurrence safety uses explicit relationship evidence. It does not infer an old missing relationship from dates or task creation order. Deletion uses the transaction’s checkpoint snapshot to bridge explicit next/created-from links across consecutively deleted nodes to unique surviving endpoints. No endpoint clears the link; ambiguous branches retain ghost evidence and a cyclic component is not reconnected. `repeatSourceId` is unchanged, without rerooting or guesses from dates/creation order. Only recurrence metadata of surviving tasks is adjusted; user text, deadlines and subtasks stay intact. The confirmed single/batch/clear and round-trip/Undo tests cover this correction; they do not invent old relationships where evidence is missing.

This lifecycle behavior passed checks with isolated subprocesses and files, without a browser/network dependency; the signal regression requires POSIX.
